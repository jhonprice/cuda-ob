创建参数

用作**参数/权重**的张量（本质是需要计算其梯度并更新值）
- 可学习参数的张量需要一个**梯度**
- 创建：`requires_grad=True`
- *发送到设备的速度有点慢*


四种创建方式，表现为
1. 不使用GPU才能正常工作
2. 不起作用：会丢失梯度
3. 冗长，但有用
4. 推荐方法

注意：
- 不同设备，不同软件包，即使随机种子相同，伪随机数序列也不同

>在PyTorch中，每个以下画线(`_`)结尾的方法，如上面的 `requires_grad_( )`方法，都是在**原地修改**。也就是说，它们会修改底层变量。

```python
# 1 默认CPU张量
torch.randn(1,requires_grad=True,dtype=torch.float)

# 2 发送到设备(会丢失梯度) 

torch.randn(1,requires_grad=True,dtype=torch.float).to(device)

# 3 先发送后设置
w=torch.randn(1,requires_grad=True,dtype=torch.float).to(device)
w.requires_grad_()

# 4 创建张量并分配设备
w=torch.randn(1,requires_grad=True,dtype=torch.float,device=device)


```

**动态计算图**：跟踪上述链式以来关系

梯度：
- `w.grad`：*梯度是累积的*
	- CPU：`tensor([-6.2250])tensor([-3.6313])`
	- GPU：`tensor([-6.7762],device='cuda:0')`

**累积梯度**
- 问题：需要使用当前损失对应的梯度来执行参数更新，不应该使用累积梯度。
- 用意：规避硬件限制
	- 数据点太多导致显存不够
	- 将**小批量**拆成**子小批量**，累计其梯度，来获得与整个小批量梯度相同的结果
- 所以更新参数后要将梯度归零

归零：`zero`
- 更新参数后要将梯度归零
	- `b.grad.zero_()`

python知识补充：
- 原地Python赋值：[Python原地运算的语义 - 知乎](https://zhuanlan.zhihu.com/p/563489205)
- [Python中with使用详解](https://zhuanlan.zhihu.com/p/15980013302)


更新参数：3种方案
- `b = b - 1r * b.grad`：在重新赋值时丢失了梯度
- `b -= 1r * b.grad`：原地分配，需要梯度的叶变量
	- pytorch从涉及任何梯度计算张量或其依赖项的每个Python操作构建**动态计算图**。
- `no_grad`函数，它允许我们对张量执行常规 Python操作，而不会影响PyTorch的计算图

> 不能简单更新参数，而不使用`no_grad`

**优化器**
- 作用：不再手动更新参数
	- `optimizer = optim.SGD([b,w],lr=lr)`
	- 梯度归零的操作也不需要手动，使用函数：`zero_grad`
- 分类
	- SGD：随机梯度下降
	- RMSprop
	- Adam
- 使用：
	- `step`方法负责更新：需要更新的参数，学习率
	- 不要被优化器的名字所迷惑：如果一次性使用所有训练数据进行更新(正如在代码中所做的那样),优化器正在执行批量梯度下降，尽管它的名字是这样的。

计算损失
- **均方误差MSE**：`loss_fn = nn.MSELoss(reduction='mean')`
	- `loss_fn`才是损失函数
	- `loss_fn(predictions,labels)`
>还可以指定要应用的简化方法，即您希望如何汇总各个点的误差——可以对它们进行平均`(reduction="mean")`或简单地求和`(reduction="sum")`。在我们的示例中，使用典型的mean来简化计算**MSE**。如果使用sum作为简化方法，实际上是在计算**SSE**(平方误差之和)。

不能直接获取numpy版本的loss张量：
- 损失张量实际上是计算梯度——要使用`numpy()`,首先需要从计算图中`detach()`张量。
- 或直接使用
	- `item`(只有一个元素的张量)
	- `tolist`(如果只有一个元素，它仍然返回一个标量)

**模型**
- 在PyTorch 中，**模型**由继承自**Module**类的常规Python类表示。
	- 虽然有`forward`函数，但不要调用`m.forward(x)`，要使用整个模型，如`model(x)`
		- 对整个模型的调用涉及额外的步骤，即处理前向和反向**钩子(hook)**

**参数**
- 使用`Parameter()`类定义了两个参数b和w,以告诉PyTorch这些作为模型类的属性的张量，应该被视为该类所*代表的模型的参数*。
- 这样做，可以使用模型的`parameters()`方法来检索所有模型参数的迭代器，包括嵌套模型的参数。然后可以使用它来提供优化器(*而不是自己构建参数列表*)。


**`state_dict`**
- 获取所有参数的当前值
- 将每个属性/参数映射到其对应的张量上。但只包括可学习的参数，因为它的目的是跟踪将被优化器更新的参数。
- **优化器**本身也有一个`state_dict()`方法，其中包含其内部状态以及其他超参数
- 状态字典也可以用于检查点模型

**设备**
- 需要将模型发送到数据所在的同一设备上。如果数据由GPU张量组成，那模型也要存在于GPU上
- `ManualLinearRegression().to(device)`

**前向传递**
- 请记住：您应该调用model(x)进行预测。不要调用model.forward(x),否则，模型的钩子将不起作用(如果有的话)。

**训练模式**
- `model.train`：模型设置为训练模式，并不实际执行训练步骤
- 某些模型可能会使用**丢弃(dropout)**等机制，这些机制在训练和评估阶段具有不同的行为。

**嵌套模型**
- 在模型中，手动创建了两个参数来执行线性回归。如果使用PyTorch的Linear模型，而不是定义单个参数
- 模型也可以包含其他模型作为其属性
- `model = nn.Sequential(nn.Linear(1,1)).to(device)`

**序列模型**(层的抽象)
- 对于使用一系列内置PyTorch 模型(如 Linear)的简单模型，其中一个模型的输出被有序地输入到下一个模型，可以使用`Sequential` 模型。
- 其他模型内部中的模型，这可能很快就会让人感到困惑，所以按照惯例这里将任何内部模型称为**层**。
